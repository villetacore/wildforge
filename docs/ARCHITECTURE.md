# Архитектура Wildforge

```
                        content/  (JSON + текстуры, общие для всех)
                        │                     │
            определения │                     │ текстуры (PNG)
                        ▼                     ▼
┌──────────────────────────────┐   WebSocket/JSON   ┌───────────────────────────────┐
│  server/  (Go)               │ ◄────────────────► │  client/  (Rust + Godot 4)    │
│  авторитетный сервер         │   ws://host:7777/ws │  3D-клиент, GDExtension       │
└──────────────────────────────┘                    └───────────────────────────────┘
```

Сервер авторитетный. Клиент шлёт только намерения (`move`, `attack`, `gather`,
`craft`…), сервер решает, что из этого произошло, и 20 раз в секунду рассылает
каждому игроку состояние того, что находится рядом с ним. Клиент ничего не считает
сам: он рисует последнее состояние и сглаживает движение между тиками.

## Файловая структура

```
wildforge/
├── content/                  ← весь игровой контент, без кода
│   ├── items.json            предметы: материалы, зелья, оружие, броня, инструменты
│   ├── recipes.json          рецепты крафта
│   ├── resources.json        добываемые узлы (дерево, камень, руда, кристалл) и где они растут
│   ├── enemies.json          враги: статы, модель, текстура, дроп
│   ├── world.json            размер мира, число врагов, стартовый инвентарь…
│   └── textures/*.png        бесшовные текстуры 128×128 (генерирует server/cmd/texgen)
│
├── server/                   ← Go
│   ├── cmd/
│   │   ├── wildforge-server/ точка входа: сборка зависимостей, HTTP, graceful shutdown
│   │   └── texgen/           процедурный генератор текстур → content/textures
│   └── internal/
│       ├── config/           флаги и переменные окружения
│       ├── content/          загрузка и валидация content/*.json (Pack)
│       ├── storage/          аккаунты (PBKDF2) и сохранения персонажей в JSON-файле
│       ├── protocol/         все сетевые сообщения (типы JSON)
│       ├── world/            генерация острова, тайлы, узлы ресурсов, коллизии
│       ├── game/             симуляция мира (один goroutine, 20 тиков/с)
│       │   ├── game.go         цикл, события, тик, рассылка
│       │   ├── player.go       вход/выход, разбор команд, движение
│       │   ├── character.go    сохраняемый персонаж, статы, инвентарь со стаками
│       │   ├── enemy.go        спавн и ИИ врагов
│       │   ├── combat.go       бой, опыт, уровни, дроп
│       │   ├── gathering.go    добыча ресурсов, респавн узлов
│       │   ├── crafting.go     крафт по рецептам
│       │   ├── items.go        предметы на земле, использование, экипировка
│       │   ├── chat.go         чат и команды /who /stats /help
│       │   └── snapshot.go     состояние для каждого игрока
│       └── netserver/        WebSocket: фаза входа, затем пересылка ввода в game
│
├── client/
│   ├── godot/                ← проект Godot (только сцена и настройки)
│   │   ├── project.godot
│   │   ├── main.tscn         одна нода WildforgeGame (класс из Rust)
│   │   └── wildforge.gdextension  путь к собранной библиотеке Rust
│   └── rust/                 ← весь код клиента
│       └── src/
│           ├── lib.rs        регистрация GDExtension
│           ├── app.rs        WildforgeGame: машина состояний (логин ↔ игра), связывает модули
│           ├── net/          фоновый поток WebSocket + типы протокола
│           ├── session.rs    данные текущей сессии (без нод Godot)
│           ├── content.rs    поиск content/, загрузка текстур, кэш материалов и иконок
│           ├── input.rs      клавиатура → команды
│           ├── world/        3D-сцена
│           │   ├── terrain.rs     чанки рельефа 32×32, берега, анимированный океан
│           │   ├── resources.rs   деревья/камни/руды через MultiMesh, тряска при добыче
│           │   ├── entities.rs    игроки, враги, предметы, полоски HP, интерполяция
│           │   ├── models.rs      процедурные low-poly модели
│           │   ├── effects.rs     всплывающий текст, кольца ударов
│           │   ├── camera.rs      камера сверху под углом с зумом
│           │   └── environment.rs небо, свет, тени, туман
│           └── ui/           экран входа, HUD, окно крафта
│
├── scripts/                  run-server.sh, run-client.sh
└── docs/ARCHITECTURE.md
```

## Сервер (Go)

**Поток данных:**

```
сокет ──► netserver ──(Join/Input/Leave)──► game (единственный владелец состояния)
                                              │  тик 50 мс: игроки → враги → предметы
                                              │             → узлы → респавн → сохранение
                                              ▼
сокет ◄── writer goroutine ◄── chan []byte ◄─ snapshot (у каждого игрока свой)
```

- **Никаких мьютексов в игровой логике.** Всё состояние мира принадлежит одной
  goroutine (`game.Run`). Сетевые горутины только кладут события в канал.
- **Медленный клиент не тормозит мир.** Исходящий канал игрока буферизован, и если он
  заполнен, сообщение просто выбрасывается (следующий снапшот всё равно придёт).
- **Контент — это данные.** `game` и `world` знают только типы из `content`.
  Новый предмет, рецепт, врага или ресурс можно добавить, правя JSON, без изменений в коде.
  При старте `content.Load` проверяет все ссылки (рецепты, дроп, ресурсы).
- **Хранилище не знает схему персонажа.** `storage` хранит персонажа как сырой JSON,
  схемой владеет `game.Character`.
- **Сохранение** происходит каждые 30 с, при выходе игрока и при SIGINT/SIGTERM.

**Игровые системы:**

| Система | Правила |
|---|---|
| Мир | остров из шума, город в центре, дороги, биомы: луг, лес, скалы, пляж |
| Ресурсы | узел занимает тайл и блокирует проход; у него `charges` добыч, потом он исчезает и через `respawn` с появляется снова |
| Инструменты | лучший инструмент нужного типа в инвентаре даёт тир; если тир ниже `min_tier`, добыть нельзя; выход = 1 + (тир − min_tier) |
| Крафт | атомарный: при нехватке места всё откатывается |
| Бой | ближайший враг в радиусе, 10% шанс крита, защита брони вычитается из урона |
| Враги | уровень растёт с расстоянием от города; агро, преследование, поводок, блуждание |
| Прогресс | опыт → уровень → HP/атака/защита; при смерти теряешь 10% золота |

## Клиент (Rust + Godot)

Godot-проект почти пустой: сцена содержит одну ноду `WildforgeGame`, всё остальное
создаётся из Rust во время работы.

```
                 ┌──────────── app.rs (WildforgeGame) ────────────┐
 Connection ───► │ on_message → Session (данные) → WorldView (3D) │
 (поток сети)    │                               → Hud/Crafting   │
                 │ InputState → Command ──────────► Connection    │
                 │ UiQueue (сигналы кнопок) ───────► Connection   │
                 └────────────────────────────────────────────────┘
```

- **Сеть в отдельном потоке** (`tungstenite`). Главный поток Godot каждый кадр забирает
  готовые сообщения через `mpsc`.
- **UI не вызывает игровой код напрямую.** Сигналы кнопок кладут `UiEvent` в очередь,
  а `app.rs` разбирает её в `process()`. Так нет повторных заимствований `&mut self`.
- **`Session`** — чистые данные (карта, каталог контента, последнее состояние «you»).
  **`WorldView`** — ноды Godot. Она пересоздаётся при каждом входе и удаляется при выходе.
- **Производительность:**
  - рельеф разбит на чанки 32×32 с отдельным мешем на тип покрытия;
  - ~8000 деревьев и камней рисуются через `MultiMesh` (по одному на часть модели);
  - исчезнувший узел — это схлопнутая трансформация, а не удалённая нода.
- **Контент на клиенте.** Описания предметов, рецептов и прочего приходят с сервера
  в `welcome`. Текстуры клиент читает из той же папки `content/textures`
  (`$WILDFORGE_CONTENT` → `../../content` от проекта → `content/` рядом с бинарником).
  Если текстур нет, всё рисуется простыми цветами.

## Протокол

JSON по WebSocket, в каждом сообщении есть поле `"t"`. Полные типы описаны
в `server/internal/protocol/messages.go` и зеркально в `client/rust/src/net/protocol.rs`.

| Направление | Сообщения |
|---|---|
| клиент → сервер (до входа) | `register{username,password}`, `login{username,password}` |
| клиент → сервер | `move{dx,dy}`, `attack`, `gather`, `craft{recipe}`, `use{index}`, `drop{index}`, `potion`, `unequip{slot}`, `chat{text}` |
| сервер → клиент | `registered`, `error{message}`, `welcome{id,name,size,terrain,nodes,depleted,content}`, `state{you,players,enemies,items,fx}` (каждый тик), `node{i,alive}`, `chat{from,text}`, `died{lost_gold}` |

`terrain` и `nodes` — строки по одному символу на тайл (`'0' + код`). Код узла — это
индекс ресурса в `resources.json` плюс 1.

## Как расширять

- **Новый предмет или рецепт:** добавить запись в `content/items.json` и
  `content/recipes.json`, затем перезапустить сервер. Клиент получит изменения сам.
- **Новый ресурс:** добавить запись в `resources.json` с полями `model`
  (`tree|rock|ore|crystal`), `texture` и `spawn` (на каких типах земли и с каким шансом).
  Порядок в файле задаёт приоритет при генерации.
- **Новый враг:** добавить запись в `enemies.json` с полем `model`
  (`slime|wolf|humanoid`), текстурой, цветом, масштабом и дропом.
- **Новая текстура:** положить PNG в `content/textures/` или добавить шейдер
  в `server/cmd/texgen` и выполнить `go run ./cmd/texgen` в папке `server/`.
- **Новая модель:** дописать ветку в `client/rust/src/world/models.rs`.
- **Новое сообщение протокола:** описать его в `protocol/messages.go`, обработать
  в `game/player.go` (`input`), добавить вариант в `net/protocol.rs` (`ServerMsg`)
  и обработчик в `app.rs`.
